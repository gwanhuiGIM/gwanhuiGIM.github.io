기계공학 전공을 통해 탄탄한 역학적 기반과 3D 설계 역량(SolidWorks CSWP)을 다졌으며, 자율주행 경진대회 팀장 경험과 두산로보틱스 부트캠프를 거치며 협동로봇(M0609) 및 AMR 기반 프로젝트를 수행했습니다. 하드웨어에 대한 이해를 바탕으로, 센서 신호 수집부터 실제 구동 제어까지 연결되는 로봇 시스템을 만들어 보았습니다.

VLA 기반 자연어 장애물 우회 Pick & Place

Doosan M0609 · OnRobot RG2 · RealSense · RTX 4060 Laptop(8GB) · 5인 팀 · 26.07.30~26.08.12

키워드
  • LLM 자연어 명령
  • 판단·안전 계층 분리
  • FSM
  • MoveIt
  • OMPL 구동 중 정지·재계획
  • GraspGenX
  • 실물 그리퍼 실측 보정
  • GPU 8GB 메모리 최적화
  • YOLO-seg
  • Docker

마트 계산대 환경에서 자연어 지시를 해석해 협동로봇이 장애물을 피해 물체를 집어 옮기는 것을 목표로 한 시스템입니다.

노트북 GPU 메모리에 맞춰 노드 사용량을 조정하고, 실물 그리퍼 치수를 직접 재서 파지 모델과 맞췄습니다.
OMPL(경로계획 라이브러리) 경로에서 이동 중 사람이 손을 넣으면 멈추고 다시 계획하는 동작을 확인했습니다.

본인 담당

  • 판단 계층(VLA)·안전 계층(FSM) 통합
  • GraspGenX↔실물 RG2 정합(실측·보정·Offset)
  • GPU 메모리 대응(GraspGenX 후보 수 조정·YOLO 노드 누적 정리)
  • 구동 중 정지 후 재계획 연결
  • 인지 실패 감지 게이트(팀 모션 코드 위에 제안·구현)
  • 실기 파라미터 yaml 정본화·launch 인자 분리

제조업 공장 산업안전 AMR 순찰로봇 및 관제 시스템

AMR 2대 · 천장 웹캠 2대 · 3인 팀 · 26.07.01~26.07.14

키워드
  • AMR 2대
  • 관제 FSM
  • 우선순위 선점
  • 최근접 로봇 출동
  • 쓰러짐·안전모 감지
  • 해제 지연(히스테리시스)
  • 실기 튜닝값 YAML 분리

천장 카메라가 쓰러짐·안전모 미착용을 감지하면 가장 가까운 AMR을 출동시키는 관제 시스템입니다.

로봇 상태 메시지 수신을 heartbeat(연결 유지 확인 신호)로 삼아 로봇별 오프라인·대기·출동·충전 상태를 관리하는 관제 FSM(상태 전환 로직)을 구현하고, 위치 정보나 Nav2(자율주행 소프트웨어) 필수 노드가 확인되지 않는 로봇은 출동 후보에서 뺐습니다.

본인 담당

  • 관제 FSM(heartbeat 기반 로봇 상태 관리·우선순위 선점) 설계와 디버깅
  • 쓰러짐 판정 규칙·메시지 전달 정책 설계와 디버깅
  • 실기 튜닝 파라미터의 launch→yaml 분리

협동로봇 핸드드립 커피 자동화

키워드
  • Doosan M0609
  • 카메라 없는 공정
  • 힘 센서·그리퍼 접점 신호
  • 5단계 핸드드립 자동화

  • 실패 단계 재실행 복구

그리퍼 신호가 1초 넘게 끊기면 정지를 요청하도록 했고, 병행 개발본에서는 잡았는지 판정할 수 없는 순간을 따로 분리해 물체를 문 채 다시 집지 않도록 했습니다.

핵심역량

  • 기계 설계와 로봇 소프트웨어를 함께 다루는 HW·SW 통합 역량
    기계공학 전공과 SolidWorks 자격을 바탕으로, 졸업 프로젝트에서 구명튜브 전달장치의 좌우 DC 모터 제어와 아두이노 회로를 직접 구성했습니다.
  • 로봇 시스템을 정의·설계·구현하고 개발 환경까지 운영한 경험
    VLA 프로젝트에서 자연어 명령을 해석하는 판단 계층과 로봇을 멈추게 하는 안전 계층이 하나의 흐름으로 동작하도록 묶었고, 인식·파지 모델은 Docker 컨테이너로 분리해 운영했습니다.
  • 오픈소스·AI 모델을 실물 로봇에 맞춰 통합한 경험
    파지 자세를 계산하는 AI 모델이 가정한 그리퍼 치수가 실물과 달라, 직접 재서 보정한 값으로 모델 결과를 실물 그리퍼에 맞췄습니다.
  • 실험 조건과 실패 원인을 기록하며 원인을 좁혀 간 경험
    에러 없이 잘못 동작하는 문제(AMR 응급 상태가 1초에 5번 바뀌던 문제 등)를 조건별로 재현하며 원인을 좁혔고, ERP42 팀에서는 그 과정을 인수인계 문서로 남겼습니다.
  • 맡은 역할에 책임을 다한 협업 경험
    ERP42 팀장으로 개발 일정 수립·공유와 실습 환경 구성을 맡았고, 부트캠프 팀 프로젝트에서는 관제 상태 관리·그리퍼 예외 처리처럼 맡은 모듈의 설계와 디버깅을 담당했습니다.
